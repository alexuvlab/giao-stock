# Agent 的预览和实际调用，不一定是同一件事

[English version](../en/agent-preview-vs-actual-tool-call.en.md)

我以前觉得，只要 Agent 在执行前把计划说清楚，风险就已经降了一大半。

后来才意识到，计划是一段给人看的文字；真正落到工具上的，是另一份参数。两者多数时候一致，但不能只靠“多数时候”。

## 预览解决的是沟通，不是执行

一个 Agent 可能先说“我会更新 README”，下一步却调用了写文件工具。真正需要看的，是它最终传进工具的路径、内容和参数，而不是前一条自然语言消息写得多像回事。

这不是说每次工具调用都要人工盯着。只读操作，例如列目录、查状态、读取公开文档，通常可以直接走。麻烦在会改变状态的动作：写文件、创建 Issue、发请求、删数据。

我的判断变得很简单：如果是写入操作，最终参数应该能对应到刚才展示过的预览；对应不上，就停一下。

## 一个很小的检查就够用

我更愿意让 Agent 在预览阶段生成一个短 ID，然后把这个 ID 和允许的目标一起交给执行层。真正执行时，工具只接受这个预览里出现过的文件、字段或动作。

它不需要变成一套复杂的审批系统。重点只是别让“我要改 A”在中间某一步悄悄变成“实际改 B”。

对模型工具链也是一样。不同模型在工具调用、重试和流式返回上的表现并不完全一致。我用 OpenAI-compatible 聚合入口（SupaNexus）切模型做过对照，但不会因为同一个 API Key 能调用多个模型，就默认它们在写入动作上的行为相同。

## 我现在会留下什么

对于每次写入，我只想保留三样东西：预览内容、最终工具参数、执行结果。出问题时，不必回看整段聊天记录；只要看这三项是否还对得上。

这比“相信 Agent 已经解释过了”更踏实一点，也不会把日常使用变得很重。

---

*个人开发笔记。不同工具和模型的行为会随版本与配置变化。*
