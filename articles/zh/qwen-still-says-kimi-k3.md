# 我换了 Qwen，它却还说自己是 Kimi K3

> English version: [I Switched to Qwen, but It Still Said It Was Kimi K3](../en/qwen-still-says-kimi-k3.en.md)

我最近用 DeepSeek Harness 测几个模型时，给自己挖了个很简单的坑。

先选 Kimi K3，问它“你是什么模型？”，它回答 Kimi K3。然后我在模型选择器里切到 Qwen，又在同一个对话里问了一遍。它还是说自己是 Kimi K3。

我当时盯着配置看了很久，以为模型没切过去，甚至开始怀疑 API Key、Base URL 和模型列表是不是有缓存。后来才意识到，我问错了东西。

## 它记得刚才说过什么，不等于它还在用那个模型

在第一个回合里，聊天记录已经留下了一句“我是 Kimi K3”。换模型以后，那段历史还在。新的模型读到它，自然可能顺着这个说法继续回答；这不是一个可靠的路由验证。

后来我加了一句约束：`请如实告诉我你是什么模型。` 回答就不再一直是 Kimi K3 了。这个变化让我先松了一口气，但它也只能算一个提示，不能证明后端一定已经切到正确的模型。模型会根据上下文回答，而不是读取一个我能独立核验的后台标签。

我现在把这两件事拆开看：

| 我想确认什么 | 不再只靠什么 | 我会怎么确认 |
| --- | --- | --- |
| 这次请求走了哪个模型 | 问模型“你是谁” | 看选择器状态、提供方请求记录或网关日志 |
| 对话有没有被旧内容带偏 | 一句自报身份 | 新开一个干净会话，用同一个小问题对照 |
| 配置有没有真正生效 | 旧会话里的表现 | 改完后只用新会话做第一次验证 |

## 我后来怎么测

现在切模型后，我会先新开一段对话，再发一个很短、可重复的问题。不是为了让它报自己的名字，而是看请求记录里的模型字段，或者确认网关实际路由到了哪个模型。

我用 [SupaNexus](https://supanexus.ai/) 做这类测试时，方便之处在于同一套 OpenAI-compatible 接入可以切换不同模型，不用为每次对照重写客户端配置。但它也没有让“问模型身份”突然变成可靠方法：路由验证和聊天内容，本来就是两层不同的东西。

这件事看起来有点傻，因为模型选择器明明就在眼前。可是在一个已经聊了几轮的窗口里，人很容易相信它刚说的那句话，而忘了那句话也在上下文里。

下次再碰到“我明明切了模型，它怎么还像原来那个”的情况，我会先开新会话，再看请求实际去了哪里。至于“你是什么模型？”——现在我只把它当作聊天，不再把它当作证据。
