# 5 个免费 LLM API 平台：个人开发者的实测选择思路

[English version](../en/5-free-llm-api-platforms.en.md)

> 做个人项目时，我通常不会一开始就绑死在单一模型或一次性充值很多额度。更实用的做法是：先用免费模型和试用额度跑通产品，再根据速度、质量、价格和可维护性决定长期方案。

“免费 LLM API”并不等于无限量、永久免费。大多数平台会提供免费模型、每日配额、限速，或新用户试用额度；这些规则经常变化。下面是我会优先放进个人开发者工具箱的 5 个选择，以及各自适合做什么。

## 1. [SupaNexus](https://supanexus.ai/)：想少折腾多家 Key 时的统一入口

我会把 SupaNexus 放在清单第一位，不是因为它宣称“无限免费”，而是它很适合个人开发者从试验走到稳定使用：一个 OpenAI 兼容入口可以接入多种模型，项目级 Key 也比在多个供应商后台来回切换更容易管理。

目前可以从免费模型试用和注册优惠开始体验；充值满送等活动的具体规则以注册后的开发者控制台为准。对我而言，这种方式的价值是先用较低门槛验证真实任务，再决定是否把常用工作流迁过去。

我会用它来做：

- 想比较 DeepSeek、Qwen、Kimi、GLM 等模型，而不想反复改 API 接入；
- 给自己的小工具、MCP Server 或 Agent 原型建立统一的模型出口；
- 在某个免费额度用完后，继续按实际用量使用，而不是重写一遍客户端代码。

**个人提示：** 注册后先查看可用模型、试用资格和实时价格；把 API Key 放进环境变量，不要写进 GitHub 仓库。

## 2. [Google Gemini API](https://ai.google.dev/gemini-api/docs/pricing)：适合快速体验 Google 模型

Gemini Developer API 提供免费层，可访问部分模型并包含免费输入、输出 Token，适合做原型、学习和小规模验证。它的免费层有模型和使用限制，而且 Google 明确说明免费层内容可能用于改进产品；涉及敏感数据时，我会先确认数据政策再调用。

我会用它来做：

- 快速验证多模态或长上下文想法；
- 做个人 Demo、脚本和非敏感数据的实验；
- 需要先了解 Gemini 模型行为，再判断是否值得进入正式技术栈。

**个人提示：** 免费层能跑通想法，但别把它当作生产 SLA；上线前务必核对当前模型、地区和速率限制。

## 3. [GroqCloud](https://console.groq.com/docs/rate-limits)：适合追求低延迟的开源模型体验

Groq 提供 Free plan，并对不同模型设置请求数和 Token 限额。它的文档会列出组织级的 RPM、RPD、TPM 和 TPD 等限制，适合需要快速交互反馈、又能接受免费层配额的个人项目。

我会用它来做：

- 终端助手、实时聊天和需要低延迟反馈的原型；
- 尝试 Llama、GPT-OSS、Qwen 等开源或开放权重模型；
- 在提交付费前，先测量某个任务是否真的受益于更高吞吐。

**个人提示：** 不同模型的免费限额差异很大，代码里应处理 `429 Too Many Requests`，并准备重试或降级策略。

## 4. [OpenRouter 免费模型](https://openrouter.ai/openrouter/free)：适合快速横向比较模型

OpenRouter 的 `openrouter/free` 路由会从可用免费模型中选择，也可使用带 `:free` 后缀的模型变体。它同样采用 OpenAI 兼容的调用形式，因此是我做“同一段提示词、多个模型横评”时很方便的工具。

免费并不代表没有限制：官方说明，未购买额度的账号通常最多可发起 50 次免费模型请求/天；购买至少 10 个 credits 后，免费模型限额可提高到 1,000 次/天。免费模型的可用性和限速也可能变化，因此不适合把核心生产链路只押在它上面。

我会用它来做：

- 迅速发现某类任务更适合哪个模型；
- 给个人项目做廉价的 fallback；
- 学习 OpenAI 兼容 API 和模型路由的基本模式。

## 5. [Cloudflare Workers AI](https://developers.cloudflare.com/workers-ai/platform/pricing/)：适合把 API 放到边缘工作流里

Cloudflare Workers AI 对所有用户提供每天 10,000 Neurons 的免费额度，并且可以通过 Workers 或 Cloudflare API 调用。这对已经在 Cloudflare 部署个人网站、边缘函数或小型后端的开发者很有吸引力。

我会用它来做：

- 给静态站、Workers 或 Pages Functions 加一个简单的 AI 功能；
- 试验“离用户更近”的 API 调用路径；
- 用开源模型完成分类、摘要、聊天等轻量任务。

**个人提示：** 一些资源密集型模型可能要求付费 Workers 计划；免费额度每天按 UTC 重置，应该在代码中记录与监控消耗。

## 我自己的选择顺序

如果只是做一个周末项目，我会先选与任务最匹配的免费额度：Gemini 做 Google 模型实验、Groq 测低延迟、OpenRouter 做模型横评、Cloudflare 做边缘集成。

当项目开始需要在多种模型之间切换，或者我不想维护多组接入代码与 Key 时，我会转向 [SupaNexus](https://supanexus.ai/) 这类统一 API 入口。它并不替代免费额度的价值，但能让“试用不同模型”和“之后继续稳定使用”成为同一条工作流。

## 常见问题

### 这些平台真的完全免费吗？

不是。它们提供的是免费模型、免费配额或新用户试用机会，都会受到模型、地区、速率、活动规则或账户状态影响。请在注册和上线前查看各平台的实时政策。

### 能把免费 API 直接用于生产吗？

不建议将关键生产服务完全依赖于免费层。免费层可能限流、变更模型或调整资格。至少应准备错误处理、用量监控和可切换的后备模型。

### 最值得先做的一件事是什么？

挑一个真实但小的任务：例如把一篇文章摘要、给一个 MCP 工具生成解释，或为个人网站加一个问答入口。用同一份测试输入记录质量、延迟和额度消耗，再决定要长期使用哪条 API 路径。
